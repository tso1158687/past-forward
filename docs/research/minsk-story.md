# 故事模式的旁白：每一句的依據

**狀態：故事模式（`src/app/data/scenarios/minsk-1941/story.ts`）的旁白依這份文件建立（2026-11-22）。之後要改任何一句，先改這份文件。**

## 使用者的決定（2026-11-22）

| # | 決定 | 說明 |
| --- | --- | --- |
| U19 | 故事模式另寫連貫的旁白，而不是直接顯示事件的說明 | 我建議只用已查證的事件文字，使用者選了另寫；條件是每句都要對得上研究文件 |
| U20 | 按「下一站」翻頁，由讀者決定何時前進 | 另外兩個選項是全自動播放、兩者都有 |
| U21 | 站與站之間的日子逐日快速播過 | 另一個選項是直接跳過去 |
| U22 | 開啟網頁時是自己探索，按鈕進入導覽；自己操作時間軸就離開導覽，之後可以從同一站繼續 | 另一個選項是一開始就進入導覽 |

## 寫法的規則

- 旁白只重述研究文件裡已有的內容，不加新的史實。研究文件標為 B 或 C 級的內容，旁白裡也要讓讀者看得出不確定（例如「據 Glantz 的研究」「另有 27 日之說」）。
- 「畫面說明」類的句子（例如「淡藍色是……」）講的是這個網頁怎麼畫，依據是程式與對應的研究文件，不是史實。
- 連接用的詞（「同一天」「在後方」「接下來」）只表示時間或空間的順序，不帶新的事實。
- 不使用參考影片的旁白文字。
- 每站列出依據的來源；畫面上的「依據」一欄就是這裡的來源。

## 寫進資料時的對應

- `src/app/data/scenarios/minsk-1941/story.ts`：每站一筆 `StoryStop`，旁白照上面各表「句子」欄逐句連成段落，順序不變。
  第 2 站最後一句前面加「依蘇方將領的回憶錄，」；其餘句子照錄。
- 每站的 `sourceIds` 照「來源」欄。事件編號照「事件」欄。
- 鏡頭：寫「同事件」的，用該事件資料裡的 `camera`；寫「全圖」的不給鏡頭，由畫面回到起始視角。
