# Past Forward 歷史進行式

3D 互動式歷史故事書：把歷史戰役紀錄片裡的立體戰略地圖、部隊移動與戰線變化，
變成可以自己操作時間軸與地圖的網頁。

| 項目 | 名稱 |
| --- | --- |
| 英文品牌 | Past Forward |
| 中文品牌 | 歷史進行式 |
| 第一個歷史章節 | Past Forward: Operation Barbarossa／歷史進行式：巴巴羅薩行動 |
| 長期方向 | 歷史探索、架空歷史、AI 戰略模擬 |

第一個章節的 MVP 範圍是 1941 年 6 月 22 日至 7 月上旬中央集團軍群在明斯克方向的攻勢。

目前進度：**Milestone 3 進行中**。時間軸上有 12 個對照過史料的事件，地圖上有 11 支部隊的棋子（德軍 5 個摩托化軍與 2 個集團軍、蘇軍 4 個集團軍），每一筆位置都附來源與核對程度；換日期時棋子會滑行，後面留下軌跡線。還沒有戰線與控制區。

## 啟動

需要 pnpm 與 Angular CLI 22 支援的 Node.js 版本（22.22.3 以上的 22.x、24.15 以上的 24.x，或 26 以上）。

```bash
pnpm install
pnpm start        # 開發伺服器，http://localhost:4200
```

| 指令 | 用途 |
| --- | --- |
| `pnpm start` | 開發伺服器 |
| `pnpm build` | 正式建置，輸出到 `dist/` |
| `pnpm test` | 單元測試（Vitest，跑一次） |
| `pnpm test:watch` | 單元測試（監看模式） |
| `pnpm lint` | ESLint |
| `pnpm format` / `pnpm format:check` | Prettier |
| `pnpm bake:map` | 從開放資料重新產生 `public/map/` 的地形、河流與國界 |

## 操作

- 拖曳：平移
- 右鍵拖曳（觸控為雙指）：旋轉與傾斜
- 滾輪（觸控為雙指縮放）：縮放
- 點選城市：鏡頭聚焦並顯示資訊
- 「回到全圖」：回到初始視角
- 時間軸：播放／暫停、拖曳滑桿切換日期、調整播放速度
- 事件：點時間軸上的色塊，或用事件面板的左右按鈕逐一瀏覽；選取後鏡頭會移到事件地點
- 部隊：把游標移到棋子上會顯示番號全名；點棋子可以看它這一天的位置依據、核對程度、來源，以及這枚棋子代表部隊的哪一點

## 畫面上的內容從哪裡來

| 內容 | 來源 | 說明 |
| --- | --- | --- |
| 地形 | AWS Open Data 的 Terrain Tiles（zoom 8） | 真實高程，約 0.4 公里一格；高度誇張 30 倍 |
| 河流 | Natural Earth 1:10m（公有領域） | 現代河道 |
| 城市 | Natural Earth 與 OpenStreetMap | 現代座標與今日常見譯名，並非 1941 年當時的名稱 |
| 國界 | OpenHistoricalMap（CC0），見 [docs/research/minsk-borders.md](docs/research/minsk-borders.md) | 1941 年 6 月 22 日開戰時的德蘇邊界；走向對照過 1939 年 10 月德蘇劃界議定書描述的地點 |
| 事件 | 逐項對照史料，見 [docs/research/minsk-events-verified.md](docs/research/minsk-events-verified.md) | 每個事件附來源；地點標的是今日城鎮中心，不是橋或戰場的確切位置 |

事件的可信度有三種，畫面上用顏色區分：

| 顏色 | 意思 |
| --- | --- |
| 綠 | 主要內容已親自核對來源原文；尚未核對的細節寫在該事件的說明裡 |
| 黃 | 有學術著作記載，但尚未核對原書 |
| 橘 | 可靠來源說法不一；畫面採用其中一說，並註明其他說法 |

部隊的棋子（藍色是德軍，棋面的字是兵種：甲＝摩托化軍、步＝步兵集團軍；紅色加紅星是蘇軍集團軍；下方的數字是番號）：

| 部隊 | 位置怎麼來的 | 說明 |
| --- | --- | --- |
| 德軍 5 個摩托化軍 | 1942 年德軍參謀本部圖集的每日態勢圖，見 [docs/research/minsk-unit-positions-daily.md](docs/research/minsk-unit-positions-daily.md) | 每晚一個位置。標記放在該軍當晚最靠前的裝甲師主力所在，不是軍部 |
| 德軍第 4、第 9 集團軍 | 同一份圖集上的司令部旗號 | 標記是司令部，不是它轄下各軍、各師所在 |
| 蘇軍 4 個集團軍 | 蘇方的回憶錄與研究，見 [docs/research/minsk-unit-positions.md](docs/research/minsk-unit-positions.md) | 只在有蘇方記載的日子出現，所以時有時無；不使用德方對蘇軍位置的判斷 |

選一個日期，看到的是那天**晚上**的態勢。棋子的外圈：實線是來源指明的位置，虛線是約略位置（來源只給一帶，或地點對不準）。
點開棋子可以看到這一筆是我親自核對過原圖或原文，還是由他人讀出、尚未親自核對。

換日期時棋子滑到新位置，這只是畫面轉場，不代表部隊實際走的路線。棋子後面的線連的是它前幾晚有來源的位置；
標記改為代表部隊的另一部分時（例如領頭的師被調到別的軍），棋子會淡出再淡入，線也不相連。

還沒有的：戰線、控制區。這些尚未製作，所以不顯示，也不用假資料代替。
時間軸的起訖是 1941 年 6 月 22 日至 7 月 9 日，共 18 天，依蘇方官方對這場戰役的分期。

## 專案結構

分成四層，依賴只能往下：`ui` 可以用 `scene`、`data`、`core`；`scene` 與 `data` 只能用 `core`；`core` 不依賴其他層。

```
src/app/
  core/     純 TypeScript，不依賴 Angular 與 three.js（可單獨測試）
    geo/      經緯度型別、地圖投影、高度格網取樣
    timeline/ 日曆換算、時間軸狀態（播放、暫停、跳轉、推進）
    history/  劇本、事件、來源與部隊的型別；由日期推導世界狀態
    i18n/     多語系文字型別
  data/     靜態資料：城市、河流名稱、地圖資產載入、劇本（scenarios/minsk-1941：事件、部隊、國界與來源）
  scene/    three.js 呈現層：地形、河流、國界、標籤、單位與事件地點標記、鏡頭。不含歷史邏輯，也不依賴 Angular
  ui/       Angular 元件（地圖、時間軸、事件面板）、時間軸狀態管理與介面文字
tools/      離線資料烘焙腳本
public/map/ 烘焙產生的地形、河流與國界資產
docs/       專案概要、路線、決策紀錄、開發日誌、史料研究
```

- 所有資料一律以經緯度儲存，只有 `core/geo/map-projection.ts` 知道經緯度如何對應到場景座標。
- `scene/map-scene.ts` 是 3D 層唯一對外的入口，介面只有 `focusOn`、`resetView`、`setUnits`、`setPlaces`、`dispose` 與事件回呼。
- 時間以「戰役日」表示：距章節起始日的天數，可帶小數。某一刻地圖上有什麼，完全由 `core/history/world-state.ts` 的純函式從劇本與日期算出來。
- 介面文字集中在 `ui/i18n/messages.zh-TW.ts`；新增語系時補一份同樣形狀的物件即可。

## 已知限制

- 地形解析度約 0.4 公里，拉到最近時會看得出模糊。
- 投影是簡單的等距圓柱投影，區域南北邊緣的東西向比例誤差約 6%。
- 河流線與低解析度地形不完全貼合，因此河流不做深度遮蔽，一律畫在地形之上。
- 國界只畫了 1941 年 6 月的德蘇邊界；邊界兩側的行政區界（東普魯士、總督府、各加盟共和國）與 1939 年以前的波蘇舊邊界沒有畫。
- 德蘇邊界的走向取自志工編輯的 OpenHistoricalMap，只對照過條約描述的地點，沒有逐公里比對條約附圖。
- 開戰頭幾天各軍擠在邊境，棋子仍會互相重疊。
- 軌跡線整段保留，到 7 月上旬線很多，目前不能關掉或只看某一支部隊的。
- 第 57 摩托化軍的棋子 6 月 28 日會在明斯克附近淡出、在西邊約 100 公里處淡入：領頭的裝甲師從這天起在圖集上改畫在另一個軍旁邊（decisions U10、D31）。
- 開發伺服器關閉了熱更新，改檔後是整頁重新載入（原因見 decisions D18）。
